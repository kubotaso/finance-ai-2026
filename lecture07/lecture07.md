# CSVとJSON、観測単位

## CSVはtext file

CSVは、値を `,` で区切って並べたtext fileです。

```
Date,Code,C,Vo
2024-08-05,01110,"2,467",27465800
2024-08-05,03330,,0
```

1行目が見出しで、列の名前が並びます。2行目から下が値です。値の中に `,` があるときは、`"2,467"` のように引用符で囲みます。値がないところは、`,,` のように何も書かれていません。

VS Codeで開くと、書かれている文字がそのまま見えます。Excelで開くと、Excelが値を解釈して表示します。`01110` は数の1110に、`2024-08-05` は日付に、`"2,467"` は数の2467になります。Excelで上書き保存すると、解釈された形でfileが書き換わります。

## 同じ表をJSONで書くと

表を文字で書く形式は、CSVだけではありません。上と同じ2行をJSONで書くと、次のようになります。

```json
{"data": [
  {"Date": "2024-08-05", "Code": "01110", "C": 2467, "Vo": 27465800},
  {"Date": "2024-08-05", "Code": "03330", "C": null, "Vo": 0}
]}
```

1行が `{ }` で囲んだ「列の名前と値の組」です。それが `[ ]` の中に並び、`"data"` という名前の下に入っています。CSVは表だけを書く形式ですが、JSONはこのように入れ子にできるので、行の並びと、それ以外の情報を同じfileに入れられます。第8回で使うAPIは、この形で返答します。

CSVと比べると、値の種類の扱いが違います。

- `"01110"` は引用符が付いているので文字列です。先頭の0は消えません。CSVで `dtype={"Code": str}` が要るのは、CSVにこの区別がないからです。
- `2467` は引用符がないので数です。CSVの `"2,467"` のように、桁区切りのために引用符で囲む必要がありません。
- 値がないところは `null` と書きます。CSVの空欄と同じく、pandasでは `NaN` になります。
- `Date` は文字列です。JSONにも日付の型はないので、`pd.to_datetime` はどちらの形式でも要ります。

## 1行が何を表すか

`prices.csv` の1行は、1つの銘柄の1日です。3社×488日で1,464行になります。

| Date | Code | C |
|---|---|---:|
| 2024-01-04 | 01110 | 2600.0 |
| 2024-01-05 | 01110 | 2670.0 |
| … | … | … |
| 2024-01-04 | 02220 | 3000.0 |

1行を1日にして、銘柄ごとに列を並べる形もあります。今回の表は、銘柄と日付の組が1行で、列は価格や出来高の種類です。J-Quantsから取得する表も、この形です。

## fileとDataFrame

DataFrameは、pandasが表を扱うためのデータの形です。行と列があり、列ごとに名前と型（整数、小数、文字列、日付）を持ちます。Excelのシートに似ていますが、列全体をまとめて計算したり、条件に合う行だけを取り出したりする操作が、1行のcodeでできます。第6回のlistが「値の並び」だとすれば、DataFrameは「名前の付いた列の並び」です。

DataFrameの作り方は2つあります。1つは、この回のようにCSV fileを `pd.read_csv` で読む方法です。もう1つは、`pd.DataFrame({"Code": ["01110", "02220"], "C": [2600.0, 3000.0]})` のように、列名をkey、値のlistを値にした辞書から作る方法です。第9回の会計の表は、後者の形で小さな表を自分で作ります。

CSV fileは、diskに保存された文字の並びです。pandasで読むと、kernelのメモリの中にDataFrameができます。DataFrameの列を書き換えても、CSV fileは変わりません。書き換えた表は、`to_csv` で書き出すとfileに残ります。

## 列と行を選ぶ

```python

short[["Date", "Code", "C"]]
```

列の名前を `[ ]` に入れると、その列が出ます。複数の列は、名前のlistを入れます。

## listとDataFrame、関数とmethod

listとDataFrameの列では、同じ `* 2` でも結果が違います。

```python

```

`len(short)` は、関数 `len` に表を渡す書き方です。`short.head()` は、表が持っているmethod `head` を呼ぶ書き方です。`short.shape` のように `( )` を付けないものは、表が持っている値で、`short.shape()` と書くと `TypeError` になります。

`short` はPythonの変数の名前で、`"C"` は表の中の列の名前です。列の名前は文字列なので、引用符で囲みます。

# 型・日付・欠損・並べ替え

## 銘柄コードは文字列

```python
short = pd.read_csv("data/prices_short.csv", dtype={"Code": str})
```

`dtype={"Code": str}` を付けて読むと、先頭の0が残ります。 銘柄コードは、足したり平均したりする数ではなく、銘柄を区別する記号です。第11回で複数の表を銘柄コードで結合するときも、片方の `Code` が文字列、もう片方が整数だと、結合の段階でerrorになります。

## 数に見える文字列

`"2,467"` は数に見えますが、文字列です。文字列の列に2を掛けると、`2,4672,467` のように文字がつながります。`,` を消してから数に変換します。

```python
short["C"] = pd.to_numeric(short["C"].str.replace(",", ""))
```

`,` を残したまま `pd.to_numeric` を使うと、`ValueError` で止まります。空欄だった値は `NaN` になります。

型の直しは、Codexにまとめて頼めます。

```text

読んだ後の型の一覧と、Codeの値の一覧を表示して。
```

`Code` に `01110` のように先頭の0が残っているか、`Date` が `datetime64` になっているかを確かめます。

## 日付

タイムスタンプは、ある時点の日付や時刻を表す値です。例えば `2024-08-05 15:00:00` は、2024年8月5日15時を表します。今回の株価データは1日単位なので、`Date` には観測日だけが入っています。

読んだ直後の `Date` は、`2024-08-05` という文字列です。見た目は日付でも、文字列のままでは期間で絞ったり、前の日との間隔を数えたりできません。`pd.to_datetime` で日付型（`datetime64`）にすると、それができるようになります。読むときに `parse_dates=["Date"]` を付けても、同じ型になります。

書き方が `2024/8/5` のようにそろっていないfileでは、もう1つ問題が起きます。文字列は左から1文字ずつ比べるので、`"2024/10/1"` が `"2024/8/5"` より前に並びます。日付型にすると、日付の順に並びます。

## 並べ替え

`prices_short.csv` は新しい日付が上にあります。`sort_values(["Code", "Date"])` は、まず銘柄で、同じ銘柄の中では日付で並べます。前の日との変化率は、この並びを前提に計算します。

## 欠損と0

Retail Cの2024年8月5日は、終値が空欄、出来高が0です。売買が成立しなかった日です。

- 終値は、取引がなかったので値がありません。pandasでは `NaN`（欠損）になります。
- 出来高は、売買された株数が0株だったので、0という値があります。

`NaN` は Not a Number の略で、数の列に値がないことを表す印です。計算に失敗した結果ではありません。

`isna().sum()` で、列ごとの欠損の数が分かります。平均を計算すると、欠損の扱いで結果が変わります。

| 計算 | Retail Cの3日間の終値の平均 |
|---|---:|
| `mean()`（欠損を飛ばす） | 3,893.00円 |
| `fillna(0).mean()`（欠損を0円にする） | 約2,595.33円 |

欠損を0で埋めると、売買のなかった日の株価を0円とみなしたことになります。

Codexに「欠損を処理して」とだけ頼むと、0で埋めるか、行を落とすか、Codexが決めてしまいます。どう扱うかを指示に書きます。

```text
列ごとの欠損の数を表示して。終値の欠損は埋めずにそのまま残し、平均は欠損を除いて計算して。
```

# 関数にまとめる

ワークブックの7節では、読み込みと作図を2つの関数にします。

```python
def load_prices(path):
    frame = pd.read_csv(path, dtype={"Code": str}, parse_dates=["Date"])
    frame = frame.sort_values(["Code", "Date"]).reset_index(drop=True)
    return frame
```

`plot_normalized(df, codes, start, end)` は、表・銘柄のlist・期間を受け取り、期間の最初の取引日を100にそろえた図を描きます。中で使う列は `Date`、`Code`、`AdjC` だけです。第8回にJ-Quantsから取得する表にもこの3列があるので、関数を書き換えずに使えます。

中身は第6回と同じ `def`、`for`、`return` です。引数を変えると、同じ処理が別の銘柄・期間に使えます。

関数にまとめる作業は、Codexに頼むと速く済みます。

# FREDの日経平均株価で同じ手順をたどる

`example/` は、FREDの日経平均株価（系列 `NIKKEI225`）に同じ手順を当てはめた作例です。FREDのCSVには、東京証券取引所が休みの平日にも行があり、値が空欄になっています。2024年7月1日以降の579行のうち、37行が欠損でした（2026年9月17日取得）。

2024年7月1日の39,631.06を100とすると、期間中の最大は2026年6月25日の72,366.34で、182.6にあたります。この値はCSVの20,120行目と一致しました。FREDはこの系列に著作権があるとし、出典の記載を求めています。

# この回の要点

- CSVは文字だけのfileで、型を保存しません。銘柄コードは `dtype={"Code": str}`、日付は `parse_dates` を付けて読みます。
- CSVもJSONも文字だけのfileですが、JSONは文字列と数を引用符で区別し、入れ子にできます。日付の型はどちらにもありません。
- 価格の欠損（`NaN`）と出来高の0は、意味が違います。分割をまたいで比べるときは `AdjC` を使います。
- 図の1点は、`idxmax` などで行番号を出し、CSVの行まで戻ると確かめられます。
